# Politique de correction

## Principe
Une erreur documentaire doit être corrigée rapidement sans effacer la trace de ce qui a changé. Git constitue le journal d'audit technique ; les changements substantiels doivent aussi être explicables dans le message de commit ou la release concernée.

## Catégories
- **Critique** : mauvaise attribution à une personnalité, source falsifiée, version historique présentée comme actuelle, contenu politique non soutenu par le corpus.
- **Majeure** : date, statut, niveau de certitude ou source incorrecte pouvant changer l'interprétation.
- **Mineure** : typographie, formulation ou métadonnée sans incidence politique.

## Processus
1. Identifier précisément le claim, le document ou le statut concerné.
2. Revenir à la meilleure source disponible et archiver la provenance utile.
3. Corriger le canon plutôt que seulement l'interface dérivée.
4. Mettre à jour les liens `supersedes` / `superseded_by` lorsqu'il s'agit d'une évolution réelle et documentée.
5. Rejouer validation, retrieval et tests ciblés.
6. Publier la correction avec une description proportionnée à sa gravité.

## Droit de contestation
Toute personne, campagne, parti, journaliste, chercheur ou citoyen peut signaler une erreur via une issue publique en citant la donnée concernée et une source vérifiable. Un désaccord politique avec une proposition ne constitue pas en soi une erreur du corpus.

## Non-réécriture de l'histoire
Une ancienne position correctement documentée n'est pas supprimée parce qu'elle devient politiquement gênante ou obsolète. Elle peut être remplacée, retirée ou archivée avec la relation temporelle appropriée.
